# Alertmanager Tools

eino tools for managing alerts on Alertmanager instances via the
Alertmanager v2 HTTP API.

## Design

- **Official client** — talks to the Alertmanager v2 HTTP API through the
  official Alertmanager v2 client
  (`github.com/prometheus/alertmanager/api/v2/client`, generated by go-swagger
  over the `/api/v2/` OpenAPI spec).
- **Multi-instance** — configure multiple named Alertmanager servers via a
  `Configs map[string]Config`, matching the Kubernetes/ArgoCD tool patterns.
- **Authentication** — supports Basic auth (username/password) and Bearer
  token auth via the go-openapi auth writers. Bearer takes priority over Basic.
- **TLS** — optional `TLSSkipVerify` for self-signed certificates.
- **Output limiting** — the read tool supports Go RE2 regex filters on result
  JSON and client-side pagination.
- **Read-only against Alertmanager** — the component only performs
  `GET /api/v2/alerts` against the Alertmanager HTTP API. Alert
  lifecycle (create / update / delete / silence) is managed declaratively
  via Kubernetes CRDs (`PrometheusRule`, `Silence`, `AlertmanagerConfig`
  from `monitoring.coreos.com`) through the `kubernetes_resource_*`
  tools. The `alertmanager_alert_write` tool returns structured guidance
  pointing the LLM to the right CRD and kubernetes tool, with a
  pre-filled manifest skeleton; it never calls Alertmanager.
- **Secret redaction** — a redacting transport over the official client strips
  configured secrets (bearer token, password, username, base64 basic-auth pair)
  and truncates non-2xx error payloads before they reach the LLM.

## Configuration

```go
import (
    "github.com/webcenter-fr/eino-ext/components/tool/alertmanager"
)

configs := alertmanager.Configs{
    "prod": alertmanager.Config{
        Address:     "https://alertmanager.prod.example.com",
        BearerToken: os.Getenv("ALERTMANAGER_TOKEN"),
    },
    "staging": alertmanager.Config{
        Address:  "http://localhost:9093",
        Username: "admin",
        Password: os.Getenv("ALERTMANAGER_PASSWORD"),
    },
}
```

`Config` supports `Address` (required, http/https), `Username`/`Password`
(basic auth), `BearerToken`, `TLSSkipVerify`, and `Timeout` (Go duration
string, default `30s`).

## Available Tools

| Tool Name | Type | Description |
|---|---|---|
| `alertmanager_instance_list` | Read | List configured Alertmanager instances |
| `alertmanager_alert` | Read | Read alerts (list or get-single via `fingerprint`) |
| `alertmanager_alert_write` | Guidance | Returns CRD guidance for create/update/delete intent; does NOT call Alertmanager |

## Factory Functions

```go
// All tools (read + guidance)
tools, err := alertmanager.NewAllTools(ctx, configs)

// Read-only tools (same 3 tools: alertmanager_alert_write is now a
// non-mutating guidance tool, so it is included in the read-only set)
tools, err := alertmanager.NewReadOnlyTools(ctx, configs)

// All tools with pre-configured safety middleware
tools, mw, err := alertmanager.NewAllToolsWithSafety(ctx, configs, safetyCfg)
```

`alertmanager.WriteToolNames()` returns `[]string{}` (the component has
no mutating tools; `alertmanager_alert_write` is a non-mutating guidance
tool). The safety middleware's `WriteToolNames` can be left empty.

## Tool Details

### alertmanager_alert

Reads alerts from an Alertmanager instance (`GET /api/v2/alerts` only).
Read-only (no confirmation needed). Can fetch all alerts, a single alert by
`fingerprint`, or filter by state/matchers.

| Parameter | Required | Description |
|---|---|---|
| `instance` | Yes | Alertmanager instance name from Configs |
| `fingerprint` | No | Return only the alert with this fingerprint. Takes precedence over `alertFilter`/`state` |
| `state` | No | Filter by Alertmanager state: `active`, `unprocessed`, or `suppressed` |
| `alertFilter` | No | Alertmanager matcher string (e.g. `alertname="HighCPU"`); comma-separate multiple matchers |
| `filter` | No | Go RE2 regex on alert JSON |
| `paginate` | No | Pagination with `pageSize` (default 20) and `paginateToken` |

Each result contains: `labels`, `annotations`, `state`, `startsAt`, `endsAt`
(both RFC3339), `fingerprint`, `silencedBy`, and `receivers`.

### alertmanager_alert_write

Returns structured guidance for managing an alert via Kubernetes CRDs.
**Does not call Alertmanager.** The required `operation` param selects
the intent: `create`, `update`, or `delete`.

| Parameter | Required | Description |
|---|---|---|
| `instance` | Yes | Alertmanager instance name (context only; no live call is made) |
| `operation` | Yes | `create`, `update`, or `delete` |
| `labels` | Yes | Alert labels; must include `alertname`. Pre-fills the example manifest |
| `annotations` | No | Alert annotations. Pre-fills the example PrometheusRule rule annotations |

Intent → CRD mapping:

- `create` / `update` → `PrometheusRule`
  (`apiVersion: monitoring.coreos.com/v1`) via `kubernetes_resource_apply`
  (preferred), `kubernetes_resource_create`, or `kubernetes_resource_patch`.
- `delete` → two options, both returned:
  - (A) delete/update the generating `PrometheusRule` via
    `kubernetes_resource_delete` (permanent);
  - (B) apply a temporary `Silence` CRD
    (`apiVersion: monitoring.coreos.com/v1alpha1`) via
    `kubernetes_resource_apply` (expires at `endsAt`).
- For alert routing/receivers (not alert lifecycle), use
  `AlertmanagerConfig` (`apiVersion: monitoring.coreos.com/v1alpha1`)
  via `kubernetes_resource_apply`.

The output is a JSON object `AlertGuidanceOutput` with `action`,
`message`, `recommendedTools`, `recommendedCRDs`, `examples` (one or more
manifest skeletons with the recommended kubernetes tool), and `notes`.

## Output Limiting

The read tool accepts an optional `filter` parameter (Go RE2 regex) applied
against each alert's JSON representation. Only matching results are returned.

It also supports pagination: set `paginate.pageSize` and pass the returned
`paginateToken` to fetch subsequent pages.

## Breaking changes

These tools moved from `components/tool/prometheus`, where they were named
`prometheus_alert` and `prometheus_alert_write` and configured under
`prometheus.Config.Alertmanager`. The config is now top-level
`alertmanager.Config` (keyed by instance via `alertmanager.Configs`), and the
tool names are re-prefixed `alertmanager_`. The underlying client also changed
from a hand-rolled `net/http` client to the official Alertmanager v2 client
(no user-facing wire change).

### Breaking changes (this release)

- `alertmanager_alert_write` no longer POSTs to the Alertmanager API.
  It returns structured CRD guidance instead. The tool name is
  preserved.
- `AlertWriteParams` removed fields: `startsAt`, `endsAt`,
  `generatorURL`, `dryRun`, `confirmed`. The confirmation gate is gone
  because the tool no longer mutates anything.
- `AlertWriteOutput` (Status/Action/Fingerprint/EndsAt) is replaced by
  `AlertGuidanceOutput`.
- `alertmanagerClient.PostAlerts` is removed.
- `WriteToolNames()` now returns `[]string{}`.
- `check.go` reports the write tool as `StatusOK` ("guidance tool, no
  external call required") instead of `StatusLimited`.
